# 协议配置文件指南（YAML 怎么写）

> 读完这一篇就能自己加报文。配套源：`src/main/resources/protocols/gc-32960/2016.yaml`。
> 铁律：配置语法只有本篇列出的这些，加新语法 = 先改《设计方案.md》§5.3 再实现。

---

## 1. 一张图：报文字节怎么被配置接住

以「实时信息上报 · 整车数据」为例：

```
23 23 │ 02 │ FE │ VIN×17 │ 01 │ 00 16 │ 26 10 20 17 35 00 │ 01 │ 00 0D │ 01 02 03 E8 ... │ 7A
──────┴────┴────┴────────┴────┴───────┴───────────────────┴────┴───────┴────────────────┴────
起始符 │命令│应答│  VIN   │加密│数据长 │   命令 body（采集时间）│类型│ subtype 的 body │BCC
   └ 处理 ←── 帧层是代码 (GB32960FrameAdapter)，不配置化 ──┘ │
                                  │                   │    │
   "0x02" 命令 → name「实时信息上报」                    │    │
                         body: [数据采集时间] → 先吃 6B   │    │
                         subtype["0x01"] → name + body → 逐字段吃 20B
```

## 2. 文件结构：协议 → 版本 → 厂商

### 2.1 协议清单 `protocols/protocols.yaml`

解析入口先查清单：协议 → 版本 → 厂商，三者都必须登记，且对应文件存在，否则直接解析失败（不做默认回退）。

```yaml
protocols:
  gc-32960:
    label: GB/T 32960.3 新能源汽车国标
    versions:
      "2016":
        vendors:
          - breton
```

对应配置文件：`protocols/gc-32960/2016/breton.yaml`。新增版本/厂商时，清单与文件必须同时补齐。

### 2.2 协议描述文件

命令码直接挂在根节点：

```yaml
protocol: gc-32960        # 协议 id（/api/parse 的 protocol 参数传它）
version: "2016"           # 版本，对应文件名 2016.yaml
label: GB/T 32960.3 新能源汽车国标   # 报文名前缀

"0x01":
  name: 车辆登录
  body:
    - label: 登录时间
      type: dec-time
    - label: 登录序号
      type: u2

"0x02":
  name: 实时信息上报
  body:                    # 子报文之前的固定前缀
    - label: 数据采集时间
      type: dec-time
  subtype:
    "0x01":
      name: 整车数据
      body:
        - label: 车速
          type: u2
          scale: 0.1
          unit: km/h

"0x06":
  name: 心跳               # 不写 body = 本应无数据体
```

统一格式规则：

- 命令、子类型、字段一律用 block 缩进，**不使用 `{}` flow 写法**；
- 字段一律 `- label:` 起头，一行一个属性；
- `map` / `bits` / `invalid` 也逐行写「原值: 中文」，长表更容易核对；
- 命令码/子类型码始终带引号（`"0x02"`），避免 YAML 把它解析成整数。

## 3. body 与 subtype

| 配置 | 含义 |
|---|---|
| `body: [字段...]` | 普通报文的数据体；按字段顺序吃字节 |
| `subtype: { 类型码: {...} }` | 子报文循环：`类型1B + 信息体`；信息体没有长度字节，长度由该类型的字段定义决定 |
| `body` + `subtype` 同时写 | body 是子报文之前的固定前缀（如采集时间），先解析 body，再进入 subtype 循环 |
| 只有 `subtype` | 循环从数据体第 0 字节开始 |
| 命令级不写 `body` | 期望零长度数据单元；有字节会记 `BODY_UNEXPECTED` 并原样保留 |
| 子类型不写 `body` | 无法确定长度：记 `UNKNOWN_SUBTYPE`，把该类型之后的剩余字节原样保留并停止切包 |

有 `subtype` / `subtypeRef` 即视为 stream 型，不需要写 `stream: true`。

```yaml
"0x02":
  name: 实时信息上报
  body:
    - label: 数据采集时间      # 前置前缀
      type: dec-time
  subtype:
    "0x01":
      name: 整车数据
      body:
        - label: 车速
          type: u2
          scale: 0.1
          unit: km/h
    "0x02":
      name: 驱动电机数据       # 无 body：无法切包，会记 UNKNOWN_SUBTYPE

"0x03":
  name: 补发信息上报
  body:
    - label: 数据采集时间
      type: dec-time
  subtypeRef: "0x02"           # 复用 0x02 的子类型表
```

注意：

- `body` 与 `subtype` 并存时，body 只放**定长**字段；放 `length: rest` 会把子报文区一起吃掉。
- `subtype` 与 `subtypeRef` 互斥，同时写会在启动时报错。
- 子报文没有长度字节，必须给每个会用到的类型配完整 `body`；未知/未配置类型无法确定长度，解析器会记 `UNKNOWN_SUBTYPE` 并把该类型之后的剩余字节原样保留。

## 4. 字段语法（全部能力就这几种）

字段不写 `id`：节点标识、issue path、`$` 引用统一用 `label`。

| 表达什么 | YAML | 输出 |
|---|---|---|
| 无符号整型 1/2/3/4B | `type: u1/u2/u3/u4` | 十进制 |
| 有符号 int | `type: s1/s2` | 十进制 |
| 6B BCD 时间 | `type: bcd-time` | `2026-10-20 17:35:00` |
| 6B 十进制数值时间 | `type: dec-time`（每字节一个数值：年 月 日 时 分 秒） | `2026-10-20 17:35:00` |
| 缩放/偏移/单位 | `scale: 0.1` / `offset: 1000` / `unit: km/h` | `(值-offset)×scale` |
| 枚举中文 | `map: { "0x01": 启动态 }` | 命中显示中文；未命中显示原值（如 `0x7F`） |
| 特殊值 | `invalid: { "0xFFFF": 异常 }` | 数值字段命中显示中文；未命中按类型正常转换（与 `map` 互斥） |
| 位表 | `bits: { "0": 运行, "2": 故障 }` | `bit2 故障` |
| 位段 | `segments: [{ start: 0, width: 1, values: { "1": 无CAN数据 } }]` | 每段合成值命中显中文、未命中显该段十进制；多段「；」拼接（与 `bits` 互斥） |
| 字符串 | `type: gbk/ascii, length: 16` | 解码文本 |
| 原样保留（含待定字段） | `type: raw, length: rest`（或定长） | hex + 「待核对」 |
| 循环块 | `type: group, count: "$驱动电机个数", fields: [...]` | 按前文字段值循环 |

长度除了定长数字，还可以 `length: rest`（剩余全部）或算式 `length: "$驱动电机个数*14"`。
被 `$` 引用的 label 只能包含字母/数字/中文，不要含空格或运算符。

## 5. 厂商配置

厂商配置是一份**完整独立文件**，放在 `protocols/gc-32960/<版本>/<厂商>.yaml`，结构与国标文件完全一致：

```yaml
protocol: gc-32960
version: "2016"
label: GB/T 32960.3 新能源汽车国标
vendor: XX汽车

"0x02":
  name: 实时信息上报
  body:
    - label: 数据采集时间
      type: dec-time
  subtype:
    "0x01":
      name: 整车数据
      body:
        - label: 车速
          type: u2
          scale: 0.1
          unit: km/h
        - label: XX扩展字段
          type: u1
    "0x70":
      name: 扩展报文-充电诊断
      body:
        - label: 扩展明细
          type: raw
          length: rest
```

- 选择厂商时只读这一份文件，**不回落国标**；没写的命令就是没有。
- 多个厂商 = 多份完整文件，不做 overlay；改国标后需手动同步。
- 把厂商 id 加进 `protocols/protocols.yaml` 的 `vendors:` 列表，前端下拉才能选到。

## 6. 新增/核对一个报文（三步）

1. 根节点加命令码（stream 型则在 `subtype` 里加类型码）；
2. 写 `body` 字段列表 —— **没核对标准的字段先 `type: raw` 占位，禁止凭记忆编造**；
3. 补样例回归：把真实报文 hex + 期望输出写进 `ParseEngineTest`（页面样例与测试共用同一组 hex）。

## 7. 写错了怎么看

- `BODY_LEFTOVER`：字段总长比数据体短，后面有剩余字节；
- `BODY_TRUNCATED`：字段总长超过数据体长度；
- `BODY_UNEXPECTED`：命令没配 body，但数据单元有字节；
- 节点 note「未知子报文」：`subtype` 里漏了类型码；
- 字段节点 note「非 BCD 数据」：时间类型配错（BCD 与 dec-time 混淆）。
